# 战役存档

在当前用户工作区的 `campaigns/<战役名>/` 保存。若有多局且未指定，先查看索引定位现行局；新局可默认main。不要写入技能目录、全局记忆目录或其他项目战役。用户要求纯临时对话时尊重其选择，不虚构已经保存。

最小文件集：
- `canon.md`：玩家确认的设定、与技能不同的明确规则、当前资料版本。
- `state.json`：当前回合、时地、玩家自身状态、系统融合状态、能力物品、关系和未决事件。
- `characters/protagonist.md`：玩家已确认身份、知识、已融合能力、行动习惯与关系。
- `characters/index.md`与关键NPC独立卡：身份版本、当前状态、已知信息及来源、关系、目标与发生过的事件。
- `worlds/<world-id>.md`：本战役采用版本、主世界组织、当前时空、进入途径、重要变化及资料引用。
- `turns/000001.md`等：玩家原输入、最终生效正文及状态变化。
- `timeline.md`：简短已发生事实和回合链接。

`state.json`中至少分开：
`protagonist.own_rank`、`protagonist.structure`、`protagonist.native_realm`、`protagonist.active_state`、`system.rank=125`、`system.fused`。知识和能力按实际获得记录；身份字段未知留空，不为了填表编人物。

状态条件、作用域和来源可用 `abilities[].scope`、`source`、`conditions` 记录。NPC隐藏目标与玩家已知事实分开；人类可见的本地文件不是角色自动可读的剧情物件。

有正式剧情进展才加回合。状态查询、规则解释、查Rank、重写被否决正文和后台维护不推进时间。被重写版本可存入该回合归档，但当前状态和时间线只指向最终有效版本。

每回合增量保存实际变化；转场、能力获取、身份披露、关键关系变化立即更新相关卡，不等固定轮数。每完成十个正式回合或发生上下文恢复，读取核心规则、canon、状态、主角、当前世界、本场景人物与近期有效回合，核对后再续写；无需重复通读24个世界。

读取分页时把文件相对路径、行或记录ID及知识库版本记进世界卡。技能更新不自动改写已进行战役；发现确实影响当前裁定的变化时说明并记录采用版本。没有变更就不重复维护台账。

写入失败必须如实说明，不能把“已生成正文”说成“已保存进度”。本技能创建过程不生成虚构战役或先替玩家开始游戏。
